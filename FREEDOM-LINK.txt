Starting Freedom Browser from the cloned repo
---------------------------------------------

    cd ~/projects/freedom-browser
    npm start

If that aborts with "The SUID sandbox helper binary was found, but is not
configured correctly", fix it once:

    sudo chown root:root ~/projects/freedom-browser/node_modules/electron/dist/chrome-sandbox
    sudo chmod 4755 ~/projects/freedom-browser/node_modules/electron/dist/chrome-sandbox

or start it without the sandbox (less secure, no sudo needed):

    cd ~/projects/freedom-browser && npx electron . --no-sandbox


What to expect in Freedom
-------------------------

- The sample document opens with its text, table and photograph,
  READ-ONLY: the document's feed belongs to the key in the link, and
  Freedom signs Swarm feeds only as itself.
- No wallet or vault prompt to read it.
- Opening the page immediately after starting the browser is the awkward
  case: the embedded node answers HTTP before it has peers, so the first
  attempt usually fails. Both the app bundle and the document restore now
  retry by themselves — the restore up to five times over about 26 seconds,
  showing "attempt 3 of 5" in the corner.
- No permission prompt to read this document: reading Swarm needs none, and
  its feed can only be signed by the key in the link, so a grant would
  change nothing. Creating your own document in Freedom does ask, since the
  browser then owns the feed.
- A bar along the bottom may report your node's state, e.g. browse-only
  (ultra-light) mode. That concerns publishing, not viewing; switching the
  node to light mode in Freedom's Swarm settings enables saving.
